# Project Management for Full-Stack App

Put the prompts, decisions, and acceptance criteria under version control just like code. 

Here’s a pragmatic way to do it in your monorepo so Cursor (and humans) stay aligned.

## Naming & IDs

* **Prefix + zero-padded numeric ID** (E-, F-, S-, T-, ADR-, RFC-, SYS-, AG-, TOOL-, EVAL-, BUG-).
* Slugged titles for readability: `S-0001-search-by-specialty-city.md`.
* Cross-link with `Relates-To:` lines so you can trace from story → tasks → commits/PRs.

# Minimal, repeatable templates

### Epic (epics/E-*/E-\*.md)

```md
---
id: E-0002
title: Core Provider Search & Discovery
owner: Frontend, Backend
status: planned
links: [F-0002, ADR-0002]
success_metrics:
  - "P50 search latency < 300ms at 95th percentile traffic"
  - "First meaningful result CTR ≥ 35%"
---

## Why
…short business value…

## Scope
- Location-based search
- Provider profiles (MVP fields only)

## Non-Goals
- Proprietary booking
- PHI handling

## Risks & Mitigations
- Data freshness → nightly delta sync + drift checks
```

### Feature (epics/E-*/features/F-*/F-\*.md)

```md
---
id: F-0002
epic: E-0002
title: Location-Based Provider Search
status: in-progress
owners: [FE, BE]
acceptance_criteria:
  - "Given specialty & city, results show Name, Specialty, Address, AvgRating"
  - "Unverified profiles labeled clearly"
links: [S-0001, ADR-0002]
```

### Story (epics/E-*/features/F-*/stories/S-*/S-\*.md)

```md
---
id: S-0001
feature: F-0002
title: Search by specialty and city
priority: P1
estimate: 5
status: ready
qa_owner: QA-Team
links: [T-0001, T-0002]
---

### User Story
As a patient, I want to search by specialty and city so I can find local providers.

### Acceptance Criteria
- Given homepage, when user searches "Cardiologist" + "Denver, CO" → list of verified cardiologists with {name, specialty, address, avgRating}.
- Unverified profiles show "Unverified Profile" badge.

### Negative Cases
- Empty results → show helpful empty state.
- Rate limit → show friendly error.

### Test Cases
- e2e/smoke: happy path
- e2e/negatives: unverified label, empty results
```

### Prompt (prompts/\*\*/.prompt.md)

```md
---
id: AG-0002
type: agent
purpose: "Rank provider search results by locality & specialty relevance"
model: "gpt-5"
temperature: 0.1
version: 1.2.0
input_schema: json
output_schema: json
related: [F-0002, S-0001, EVAL-0001]
changelog:
  - 1.2.0: add locality_boost and verified_penalty tunables
  - 1.1.0: normalize specialties
---

# System
You are a ranking agent optimizing for relevance, locality, and verified status.
Return strictly valid JSON.

# Policy
- Never hallucinate provider fields
- Penalize unverified profiles by 0.1
- Boost distance < 10km

# Input (example)
{
  "query":"cardiologist denver",
  "candidates":[{"id":"p1","specialty":"Cardiology","distance_km":3.2,"verified":true}, …]
}

# Output (example)
{
  "ranked_ids":["p1","p7","p3"],
  "explanations":{"p1":"nearby, specialty match, verified", …}
}
```

### Eval suite (prompts/evals/suites/EVAL-\*.yaml)

```yaml
id: EVAL-0001
suite: search-relevance
dataset: ../datasets/search_queries.jsonl
metrics:
  - nDCG@10
  - top1_match_rate
thresholds:
  nDCG@10: ">=0.82"
  top1_match_rate: ">=0.55"
```

# How this plays with Cursor (and CI)

* **Cursor tasks**: point Cursor to `proj-mgmt/08-prompts/tasks/*.prompt.md` when you want focused code-gen. Each task prompt links back to the story ID and ACs so the AI has guardrails.
* **System prompts**: keep durable ethics/quality/PHI disclaimers in `prompts/system/` and prepend/include them in Cursor sessions for any user-facing or medical text generation.
* **Prompt versioning**: treat prompts like code. Semantic-version their headers, keep a `changelog`, and reference the prompt `id@version` in PRs and commit messages.
* **CI validations**:

  * A tiny Node script (or Nx target) that validates front-matter schema across `proj-mgmt/**` (fail the build if a Story lacks ACs or a Prompt lacks version).
  * Lint that every PR touching app code references at least one `S-####` in title or body.
  * Optional: run LLM eval suites (offline metrics or golden tests) for affected prompts with changed IDs.

# Git hygiene & traceability

* **Branch naming**: `story/S-0001-search-by-specialty`, `task/T-0002-api-search-endpoint`.
* **Commit trailer**: `Refs: S-0001, F-0002`.
* **PR template**: sections for Story ID(s), ACs satisfied, screenshots/traces, eval deltas.
* **Weekly decisions log**: short bullets in `12-decisions-log/` so you never lose “why.”

# Why this works

* **Reproducibility**: prompts + ACs + evals are versioned and testable like code.
* **Debuggability**: when a result goes sideways, you can diff the exact prompt version and see which eval threshold regressed.
* **Compliance**: system prompts & disclaimers are enforced centrally; PHI scope stays explicit in `10-legal-compliance/`.
* **Agility**: small “task” prompts make Cursor productive without turning it loose on the whole app.
